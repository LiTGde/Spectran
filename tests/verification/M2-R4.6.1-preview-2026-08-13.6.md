## User-directed behavior changes

- The passive, non-fluorescent attestation checkbox and its readiness gate were
  removed. The application no longer asks users to confirm a statement and
  does not assert it on their behalf.
- The model limitation is now attached to Transmittance type through an
  accessible information icon. It explains that Spectran multiplies source and
  transmittance wavelength by wavelength and cannot represent fluorescence,
  where absorbed light is re-emitted at different wavelengths.
- Applied metadata records `filter_model_scope = "passive_non_fluorescent"`
  and the complete limitation text for future audit exports. It does not record
  false user consent.
- A valid complete Total-transmittance filter is Ready without a separate
  passive-filter action. Internal and Unknown qualifications, scattering
  geometry, tail choices, and large-gap acknowledgements remain unchanged.

## Tooltip implementation decision

The user preferred `bslib::tooltip()`. The installed bslib 0.12.0 implementation
calls `tag_require(version = 5)` and therefore requires Bootstrap 5. Spectran's
current `shinydashboard` application uses Bootstrap 3. Loading both runtimes or
migrating the entire application within this focused revision would create a
framework conflict and a broad regression surface.

The revision therefore uses semantic HTML and scoped CSS with the existing
Bootstrap 3 shell. The information trigger is a native button with an accessible
name and `aria-describedby`; its adjacent element has `role="tooltip"`. The
tooltip is displayed on hover and keyboard focus, remains available when the
trigger is tapped and retains focus, and requires no bespoke JavaScript or new
dependency.

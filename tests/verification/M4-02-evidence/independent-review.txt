Findings
--------

M4-UX-R01: Return to Introduction loses the learning context and keyboard focus
State: open. Importance: acceptance defect, modest severity.
Scope: production-bound, new Introduction/explanations return path.
Reproduced in German and English at 1440px. Return journeys were also exercised
at 320px; the detailed focus reproduction below is the desktop evidence.
Steps:
1. Activate the learning-area button in Introduction with Enter.
2. Open a topic, or remain on the overview.
3. Activate Back to Introduction / Zurueck zur Einfuehrung with Enter.
4. Continue with Tab.
Observed: Introduction returns to its top. Focus leaves the learning button;
there is no visible focus on a useful content target. Further Tab navigation
starts again at Toggle navigation, instead of continuing after the learning
button. The original learning section is well below the viewport on mobile.
Expected: return to the originating learning button with visible focus and its
surrounding learning section in view. The next Tab should continue naturally.
Impact: keyboard users lose their place and must traverse/scroll the page again.
Requested change: restore the Introduction learning action as the return target,
matching the successful material-help return behavior.
Regression surface: both language variants, repeated visits, topic changes,
mobile scroll position, material-help and light-path-help returns.
Evidence: 04-de-intro-return-focus.jpg, 16-en-intro-return.jpg and recorded
visible accessibility focus transitions. A control check succeeded: material
help returned focus to its original help button with the draft intact, and
English path help returned focus with the saved comparison intact.

M4-UX-R02: Collapsed navigation leaves invisible keyboard targets
State: open. Importance: acceptance defect, moderate severity.
Scope: production-bound navigation, explicitly included in this slice.
Journeys/viewports: DE and EN 1440px collapsed sidebar; EN 320px closed mobile
sidebar. Expanded mobile two-line labels were separately checked at EN 390px
and DE 320px.
Steps:
1. At desktop, focus Toggle navigation and press Enter to collapse the sidebar.
2. Press Tab twice: focus reaches the Introduction sidebar link.
3. Continue to the Transmission/Reflection menu item.
4. Press Enter on that invisible item.
Observed: the sidebar and its links are absent visually, but Tab still visits
them. No focused menu target is visible. The hidden material item activates
the material workspace on Enter, confirming the key input was delivered.
The same invisible Introduction target occurs with the mobile menu closed.
Expected: every Tab stop is visible. A fully hidden menu should not contribute
focusable links until opened, or collapsed navigation should provide visible,
usable controls with focus indication. Preserve the requested two-line labels
and separate icons when expanded.
Impact: users encounter several invisible stops and can change sections without
knowing which action they are about to activate.
Requested change: make collapsed/closed navigation focus behavior agree with
its visible state, with a predictable focus target when closing the menu.
Regression surface: DE/EN, expanded/collapsed/mobile navigation, mouse/Enter
activation, forward/reverse Tab, the new material menu item and adjacent links.
Evidence: 18-en-collapsed-hidden-focus.jpg, 27-en-mobile-hidden-focus.jpg,
31-de-collapsed-hidden-focus-1440.jpg, 32-de-material-menu-hidden-focus.jpg.
Visible accessibility state identified the focused links; Enter then visibly
opened the material module. This is not a browser-controller failure.

M4-UX-R03: Repeated Introduction learning entry reopens the previous topic
State: open. Importance: acceptance defect against the explicit entry contract.
Scope: production-bound Introduction learning button.
Journeys/viewports: DE desktop and 320px; EN desktop.
Steps:
1. Use Introduction's Open explanations / Erlaeuterungen oeffnen button.
2. Choose a topic, for example Age and the eye or the light-path topic.
3. Return to Introduction and activate the learning button again.
Observed: a fresh session initially opens the overview, but repeated entry
retains the previous topic. The DE 320px check reopened Alter und Auge; the EN
desktop check reopened Steps and combined effects in the light path.
Expected: this Introduction action opens the topic overview on every activation,
as explicitly requested. Contextual material/help buttons should still open
their specific topics.
Impact: the promised general learning entry depends on unrelated prior browsing
and requires an extra All topics action to reach the intended destination.
Requested change: make the Introduction button's destination explicitly the
overview while retaining origin tracking and the corrected Back focus target.
Regression surface: first/repeated entry, entry after contextual material help,
both languages, both widths, overview selection and contextual topic links.
Evidence: 43-de-learning-entry-retains-old-topic.jpg and
48-en-learning-entry-retains-old-topic.jpg.
